# Product on Shelf — Pricing Sheet schema

Design for the **data-integration phase**: replace every flow's mock `CATALOG` / `VENDORS` / knobs
with rows read from one Google Sheet, served to the page via `google.script.run`. The pricing
**formulas stay in code** (the `priceOption()` / `priceCluster()` seams); the Sheet holds **list inputs
and tunable levers** only.

> **Upstream**: these per-product tabs are the **read-model** consumed by `getPricing()` →
> `window.PRICING`. They are **regenerated by `buildCatalog()`** from the normalized backbone in
> [DB_SCHEMA.md](DB_SCHEMA.md) (the central "Database GG-Sheet" synced from price emails / tracking
> sheets / RFQ_DB / NotebookLM). This workbook stays the proven read path; the backbone is the new
> write/sync path that feeds it.

## Principles

- **One tab per product**, mirroring each flow's current catalog 1:1 — the least surprising thing for
  a presale to maintain ("the Firewall tab") and a clean 1:1 read in Apps Script. Plus a handful of
  **shared tabs** for things that repeat across flows.
- **All amounts THB, list/cost — pre-buffer.** The ×1.20 negotiation buffer, ×1.20 growth buffer,
  and the SLA / location multipliers live in the `Knobs` / `Multipliers` tabs so they're tunable
  without code.
- **Header row is the contract.** Apps Script reads by column header, not position, so columns can be
  reordered and new ones appended without breaking the reader.
- Keep a `_meta` tab: `version`, `last_updated`, owner, and a one-line note per tab.

## Apps Script integration plan

1. **`Code.gs`** — switch `doGet` to `HtmlService.createTemplateFromFile('index').evaluate()` (the
   `include()` helper is already staged for this).
2. **`getPricing()`** — open the workbook by ID (`SpreadsheetApp.openById`), read each tab with
   `getDataRange().getValues()`, map rows → objects keyed by header, assemble one `PRICING` object
   shaped like the current in-code structures. Wrap in `CacheService.getScriptCache()` (~10 min TTL)
   so the Sheet isn't re-read on every page load.
3. **Page bootstrap** — inject the object once at render: `<?!= 'window.PRICING=' + getPricingJson() ?>`
   (or fetch via `google.script.run.withSuccessHandler`). Each flow's IIFE reads
   `window.PRICING.firewall` etc. instead of its inline `CATALOG`; the `priceOption()` / `priceCluster()`
   math is untouched.
4. **Cutover order** — wire one flow (Firewall) end-to-end as a vertical slice, confirm parity against
   the current mock numbers, then move the rest. Buffer/multipliers move from code constants to
   `Knobs` / `Multipliers` reads in the same step.

## Open decisions

- **Per-product tabs (recommended here) vs one normalized `Catalog` tab** with a generic
  `capacity_metric` / `capacity_value` column. Per-product is easier to maintain and reads 1:1 to the
  code; normalized is fewer tabs but mixes unlike pricing models. Easy to switch later — the reader is
  the only thing that changes.
- **Where the buffer/multipliers live** — proposed in the Sheet (tunable by you). If you'd rather keep
  them fixed in code, drop the `Knobs` / `Multipliers` tabs and read only catalog rows.
- **Email price-pull & Chat webhook** — out of scope for this schema (a later sub-phase); this draft
  covers the **Sheet lookup** that replaces the mock catalogs.
